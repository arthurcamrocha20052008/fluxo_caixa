# GUIA DO PROJETO FLUXO DE CAIXA

Este documento explica a finalidade das pastas e dos arquivos encontrados no
projeto. O sistema é uma API de fluxo de caixa feita em Python com FastAPI,
SQLAlchemy, Pydantic, MySQL e Alembic.

## 1. Visão geral das pastas

### `backend/`

Contém a aplicação da API: inicialização do FastAPI, autenticação, acesso ao
banco, modelos das tabelas, validações, cálculos financeiros e rotas HTTP.

### `backend/rotasdeapi/`

Agrupa os endpoints por recurso: usuários, contas, movimentações, cálculos e
metas. Cada módulo recebe e valida requisições, verifica a identidade do
usuário e consulta ou altera os registros permitidos.

### `backend/seguranca/`

Implementa hashing e verificação de senhas. As senhas em texto puro não são
armazenadas. A emissão e validação de JWT ficam no módulo
`backend/autenticacao.py`, fora desta pasta.

### `backend/migrations/`

Contém a configuração de execução das migrações Alembic, que versionam as
alterações do esquema do banco de dados.

### `backend/migrations/versions/`

Contém uma revisão Python por alteração versionada:

- `20261008_0001_initial_schema.py`: cria as tabelas originais do sistema;
- `20261008_0002_transfer_movements.py`: adiciona os campos que vinculam as
  duas pontas de uma transferência;
- `20261008_0003_movement_categories.py`: cria a tabela de categorias e
  normaliza categorias de movimentações já existentes;
- `adicionar_ajustes_e_resumos.py`: habilita ajustes assinados, normaliza
  categorias legadas e adiciona totais separados para transferências e ajustes;
- `limitar_tentativas_login.py`: cria a tabela que persiste o limite de
  tentativas de login por endereço cliente.

As primeiras três revisões mantêm os IDs numéricos para compatibilidade com
bancos que possam já tê-las aplicado. Os arquivos novos usam IDs descritivos.

### `backend/tests/`

Contém testes automatizados das regras financeiras e validações. Os testes
usam SQLite temporário em memória, sem alterar o MySQL configurado para uso
normal.

### `banco de dados/`

Contém dumps SQL MySQL antigos, separados por tabela, e a documentação do
esquema. As migrações Alembic são o método oficial para criar/atualizar o
esquema atual.

## 2. Arquivos da raiz

### `.env`

Arquivo local para configurações por ambiente, como `DATABASE_URL` (endereço e
credenciais de conexão ao banco) e `JWT_SECRET_KEY` (chave privada usada para
assinar tokens). Não compartilhe nem versione seus valores: podem conter
segredos.

### `.gitignore`

Lista arquivos que o Git não deve registrar, incluindo `.env`, ambientes
virtuais (`venv/`, `.venv/`), cache Python (`__pycache__/`) e arquivos `.pyc`.

### `README.md`

Apresenta o projeto, suas funcionalidades, tecnologias, estrutura, instruções
de instalação e execução, configuração do banco, migrações e testes.

### `requirements.txt`

Lista as dependências Python necessárias para instalar e executar o projeto,
como FastAPI, SQLAlchemy, PyMySQL, cryptography, Alembic, PyJWT, Pydantic,
pytest e Uvicorn.

### `pytest.ini`

Configura o pytest para localizar os módulos do backend pelo caminho `backend`
e procurar testes em `backend/tests`.

### `explicaçao.txt`

Este guia: descreve para que servem as pastas e os arquivos do repositório.

### `.git/` (quando visível)

Diretório interno criado pelo Git para guardar histórico, branches e
configuração do repositório. Não é código da aplicação e não deve ser alterado
manualmente.

### `.venv/` ou `venv/` (se existir localmente)

Ambiente virtual Python da máquina de desenvolvimento, com interpretador e
pacotes instalados. É local e ignorado pelo Git; não faz parte do código-fonte
nem deve ser documentado arquivo por arquivo.

## 3. Arquivos de `backend/`

### `backend/api.py`

Cria a instância FastAPI, define nome/descrição/versão da API, registra os
routers dos recursos e disponibiliza a rota raiz `/` para indicar que a API
está funcionando. O Swagger/OpenAPI é fornecido pelo FastAPI.

### `backend/autenticacao.py`

Cuida da autenticação por token JWT. Cria tokens com validade limitada, verifica
assinatura e expiração, encontra o usuário correspondente no banco e fornece a
dependência `obter_usuario_logado` usada pelas rotas protegidas. A chave
`JWT_SECRET_KEY` precisa ser configurada e ter pelo menos 32 caracteres.
`ACCESS_TOKEN_EXPIRE_MINUTES` permite configurar a validade; o padrão é 60
minutos.

### `backend/database.py`

Carrega variáveis do `.env`, valida a presença de `DATABASE_URL`, cria a engine
SQLAlchemy, configura a fábrica de sessões (`SessionLocal`), declara a base dos
modelos (`Base`) e oferece `get_db` para abrir/fechar a sessão em cada
requisição.

### `backend/models.py`

Declara os modelos ORM que representam as tabelas do banco:

- `Usuario`: cadastro, e-mail, CPF e hash da senha;
- `TentativaLogin`: janela e contagem persistente de falhas de autenticação por
  hash derivado do endereço cliente;
- `ContaBancaria`: proprietário, instituição, tipo, saldo, estado ativo e data;
- `CategoriaMovimentacao`: nome da categoria usada nos lançamentos;
- `FluxoDinheiro`: entrada, saída, transferência ou ajuste, com data,
  categoria e campos que associam as duas pontas de uma transferência;
- `CalculoFinanceiro`: totais e saldos apurados para um período;
- `MetaFinanceira`: objetivo, valores, datas e estado da meta.

Também define tipos SQL, chaves primárias, referências entre tabelas e regras
de exclusão/atualização.

### `backend/esquema.py`

Define os modelos Pydantic de entrada e saída da API. Valida campos antes de
chegarem à lógica da rota, incluindo formato de e-mail, requisitos de senha,
dígitos verificadores do CPF, normalização de e-mail, precisão de duas casas
decimais, categorias fixas, tipos de conta, transferências, ajustes assinados e
compatibilidade entre o tipo e o período do cálculo. Os schemas de resposta
controlam quais campos são devolvidos ao cliente.

### `backend/financeiro.py`

Implementa os cálculos de saldo e totais. Usa agregações SQL para somar
movimentações, reconstrói o saldo inicial a partir do saldo atual e dos
lançamentos posteriores à data considerada, mantém transferências e ajustes
separados dos totais comuns de renda/gasto e monta resumos de período, mês e
ano. O tipo `ResumoFinanceiro` documenta as chaves e tipos retornados. Também
persiste os resultados em `calculos_financeiros`.

### `backend/readme.md`

Documenta o backend, seus módulos, requisitos, execução, autenticação, regras
de saldo, migrações e testes.

### `backend/alembic.ini`

Arquivo de configuração do Alembic. Aponta para `migrations/`, ajusta o caminho
de importação e configura os logs. A conexão real é obtida de `DATABASE_URL`
pelo ambiente de migração, não se deve confiar em credenciais de exemplo que
possam aparecer na configuração.

## 4. Arquivos de `backend/rotasdeapi/`

### `backend/rotasdeapi/__init__.py`

Inicializador do pacote Python `rotasdeapi`. Permite importar os módulos de
rotas como um pacote.

### `backend/rotasdeapi/usuario.py`

Implementa cadastro, login e endpoints de consulta/exclusão de usuário. No
cadastro, verifica duplicidade de e-mail/CPF e armazena hash da senha. O login
verifica a senha, executa verificação de hash falsa para e-mails inexistentes,
limita cinco falhas por endereço em 15 minutos e retorna JWT. As consultas
protegidas retornam apenas o usuário autenticado; as respostas omitem o CPF.

### `backend/rotasdeapi/conta_bancaria.py`

Implementa criação, listagem paginada, consulta, atualização e exclusão de
contas. Todas as operações são limitadas às contas do usuário autenticado. A
atualização não permite alterar diretamente o saldo, e uma conta com
transferências vinculadas não pode ser removida sem tratar essas transferências.

### `backend/rotasdeapi/fluxo_dinheiro.py`

Implementa registro, listagem filtrada/paginada, consulta, atualização e
exclusão de movimentações. Atualiza os saldos das contas, impede saldo negativo
em poupança e investimento, permite saldo negativo em conta corrente e usa
bloqueio de linha nas operações financeiras. Uma transferência gera dois
lançamentos vinculados (origem e destino) e é revertida como um par.

### `backend/rotasdeapi/calculo_financeiro.py`

Implementa criação, consulta, listagem filtrada/paginada e exclusão de
cálculos. Confere se a conta pertence ao usuário e está ativa, usa as funções
de `financeiro.py` e salva o resumo do período.

### `backend/rotasdeapi/meta_financeira.py`

Implementa criação, consulta, listagem filtrada/paginada, atualização e
exclusão das metas do usuário autenticado. Calcula o estado da meta e a marca
como `concluida` quando `valor_atual` alcança `valor_meta`.

### `backend/rotasdeapi/readme.md`

Descreve os endpoints por recurso, os requisitos de autenticação, paginação,
filtros e regras para contas, movimentações, transferências, cálculos e metas.

## 5. Arquivos de `backend/seguranca/`

### `backend/seguranca/__init__.py`

Expõe `gerar_hash_senha` e `verificar_senha` como parte pública do pacote
`seguranca`.

### `backend/seguranca/seguranca.py`

Configura `PasswordHash.recommended()` da biblioteca `pwdlib` e implementa as
funções para produzir e verificar hashes de senha.

### `backend/seguranca/readme.md`

Explica o propósito do hashing, as funções disponíveis, seu uso no cadastro e
login e a relação com a autenticação JWT.

## 6. Arquivos de `backend/migrations/`

### `backend/migrations/env.py`

Ponto de entrada do Alembic. Importa os modelos para obter os metadados do
SQLAlchemy e executa as migrações em modo online (conectado ao banco) ou
offline (gerando comandos SQL).

### `backend/migrations/script.py.mako`

Modelo de texto usado pelo Alembic para gerar novos arquivos de revisão. Insere
o identificador, dependência, data e funções `upgrade()`/`downgrade()`.

### `backend/migrations/README.md`

Explica como a pasta de migrações funciona e lista comandos comuns do Alembic,
como aplicar revisões, verificar a versão corrente e atualizar um banco com
segurança após conferir o esquema e realizar backup.

## 7. Arquivos de `backend/migrations/versions/`

### `20261008_0001_initial_schema.py`

Primeira revisão: cria as tabelas iniciais de usuários, contas, movimentações,
cálculos e metas, com colunas, índices e chaves estrangeiras. A função
`downgrade()` remove essas estruturas; essa reversão pode apagar dados. O ID
interno da revisão permanece `20261008_0001` para manter compatibilidade.

### `20261008_0002_transfer_movements.py`

Adiciona às movimentações o identificador do par de transferência, sua direção
(`origem`/`destino`) e a referência à conta contraparte. Também cria índice e
chave estrangeira. O downgrade remove essas colunas. O ID interno é
`20261008_0002`.

### `20261008_0003_movement_categories.py`

Cria a tabela com categorias fixas, normaliza acentos e valores antigos vazios
ou desconhecidos para `outros`, e cria a chave estrangeira da movimentação
para a categoria. O downgrade remove a relação e a tabela. O ID interno é
`20261008_0003`.

### `adicionar_ajustes_e_resumos.py`

Adiciona o tipo de movimentação `ajuste`, campos próprios para transferências e
ajustes nos cálculos salvos, e normaliza registros de categorias antigos para
a lista fixa. Seu ID interno é `ajustes_e_resumos`.

### `limitar_tentativas_login.py`

Cria a tabela persistente que controla a janela e o número de falhas de login
por endereço cliente. Seu ID interno é `limite_login`.

### `backend/migrations/versions/README.md`

Resume o histórico das revisões e alerta para avaliar o impacto nos dados antes
de executar downgrades ou alterar revisões já aplicadas.

## 8. Arquivos de `backend/tests/`

### `backend/tests/test_financeiro.py`

Contém testes automatizados para as agregações e resumos financeiros,
transferência e reversão dos saldos, bloqueio de saldo negativo em poupança,
ajustes assinados, precisão e categorias, validação de CPF, autenticação JWT,
limite de login, isolamento entre usuários, atualização de movimentação e
correspondência do intervalo com o tipo de cálculo.

### `backend/tests/conftest.py`

Define o banco SQLite isolado, carrega a lista de categorias para os testes e
fornece um cliente HTTP de teste que substitui a dependência do banco da API.

### `backend/tests/README.md`

Documenta a cobertura atual, explica o uso de SQLite em memória e mostra como
executar a suíte com `python -m pytest backend/tests -q`.

## 9. Arquivos de `banco de dados/`

Os arquivos `.sql` são dumps MySQL legados. Eles descrevem a criação de uma
tabela cada, mas incluem `DROP TABLE IF EXISTS`; portanto, podem apagar tabelas
existentes. Para o esquema atual, prefira as migrações Alembic e não rode esses
dumps em um banco com dados sem backup e revisão cuidadosa.

### `banco de dados/fluxo_caixa_usuarios.sql`

Dump antigo para criar a tabela `usuarios`, com dados de nome, CPF, e-mail,
hash de senha e data de criação.

### `banco de dados/fluxo_caixa_contas_bancarias.sql`

Dump antigo para criar `contas_bancarias`, associando cada conta a um usuário e
armazenando instituição, tipo, saldo e estado ativo.

### `banco de dados/fluxo_caixa_fluxo_dinheiro.sql`

Dump antigo para criar `fluxo_dinheiro`, com descrição, valor, tipo, categoria,
data e conta associada. Esse dump antecede os campos de transferência pareada
e a tabela normalizada de categorias.

### `banco de dados/fluxo_caixa_calculos_financeiros.sql`

Dump antigo para criar `calculos_financeiros`, armazenando o período analisado,
totais de entrada/saída/investimento e valores inicial/final.

### `banco de dados/fluxo_caixa_metas_financeiras.sql`

Dump antigo para criar `metas_financeiras`, com objetivo, valores acumulados,
datas, estado e usuário proprietário.

### `banco de dados/readme.md`

Documenta as tabelas, campos e relações do banco e explica que Alembic é o
método atual de versionamento do esquema.

## 10. Observações importantes

- A chave JWT e o endereço/credenciais do banco são configurações locais. Não
  copie valores secretos em documentação, mensagens ou repositórios públicos.
- As rotas financeiras dependem de um JWT e limitam os dados ao proprietário
  autenticado.
- `Decimal` é utilizado nos valores monetários para evitar os erros de precisão
  comuns em valores de ponto flutuante.
- As contas correntes podem ficar negativas; poupanças e contas de investimento
  não podem ficar negativas pelas regras atuais.
- Os dumps SQL são legados e perigosos para bancos existentes por incluírem
  instruções de remoção de tabelas.
- Para iniciar a API, o README principal documenta a instalação, variáveis
  necessárias, migrações Alembic, servidor Uvicorn e execução dos testes.
